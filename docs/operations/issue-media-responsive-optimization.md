# Issue 이미지 반응형 표시·용량 최적화

작성일: 2026-08-30

## 결정

PC와 모바일은 표시 틀만 다르게 사용한다. 기기별 업로드나 별도 공개 이미지 파일을 만들지
않으며 동일한 정규화 WebP를 표시한다. 비율에 맞추기 위해 이미지 내용을 자르거나 늘리지 않는다.

| 항목                     | 적용 기준                                                   |
| ------------------------ | ----------------------------------------------------------- |
| PC·태블릿 웹, 768px 이상 | 이미지 영역 16:9                                            |
| 모바일 웹, 767px 이하    | 이미지 영역 4:5                                             |
| 이미지 맞춤              | `object-fit: contain`, 남는 부분은 배경 여백                |
| 확대                     | 이미지 클릭으로 전체 보기; 선택지 버튼 클릭과 분리          |
| 닫기                     | 닫기 버튼, 바깥 배경 클릭, ESC; 이미지 버튼으로 포커스 복귀 |
| 적용 위치                | 메인 피드·질문 상세의 선택지 이미지와 투표 후 이미지 쌍     |

기존 `cropMode` API/DB 값은 호환성을 위해 유지한다. 해당 웹 컴포넌트에서는 `COVER` 값도
전체 이미지로 표시한다. 프로필 아바타, 운영 콘솔, Library 선택기, 네이티브 앱은 이번 UI 변경 대상이 아니다.
이미지 로딩이 실패해도 선택지 텍스트와 투표 기능은 유지한다.

## 저장 정책

`apps/api/src/modules/issue-media/image-processing.ts`의 공통 처리 경로에 적용한다.

- 정책 버전: `which-issue-media-webp-v2`
- JPEG·PNG·WebP 입력, 최대 10 MiB·디코딩 4천만 픽셀 제한 유지
- 방향 보정 → 긴 변 최대 1280px로 비율 유지 축소 → sRGB 픽셀 정규화 → WebP 인코딩
- 작은 입력은 확대하지 않는다. EXIF 등 원본 메타데이터를 출력에 복사하지 않는다.
- 기본 WebP 품질 82, effort 5, smartSubsample 활성화, 알파 품질 100
- PNG·WebP는 같은 정규화 픽셀에서 lossless 후보도 생성한다. 손실 압축보다 같거나 작을 때만 채택한다.
- 후보는 메모리에서 비교하고 최종 1개만 기존 Staging/Published 수명주기에 전달한다.
- 원본 SHA-256, 최종 WebP의 perceptual hash, 입력·출력 크기 기록을 유지한다.
- 정규화 검수 근거 JSON에 정책 버전·최대 해상도·선택한 인코딩·품질을 추가한다.

예: 2400×3000은 1024×1280, 2560×1440은 1280×720, 320×400은 그대로 저장한다.
화면의 표시 비율과 저장 파일의 실제 비율은 다를 수 있다.

lossless는 **축소·정규화 이후 픽셀**에 대한 무손실이다. 원본 고해상도를 보존한다는 뜻은 아니다.
모든 사진을 특정 KB 이하로 만들기 위해 화질을 반복해서 낮추지는 않는다. 사진의 복잡도에 따라
용량 절감 폭은 다르며 원본보다 항상 작거나 모든 글자가 선명하다고 보장하지 않는다.

## 처리 비용·보안 경계

- 디코딩·방향 보정·축소는 한 번 수행하고, 두 인코더는 최대 1280px인 동일 픽셀을 사용한다.
- 동시 처리 2개·응답 제한 10초는 유지한다. 응답이 타임아웃되더라도 실제 이미지 작업이 끝나기
  전에는 처리 슬롯을 반환하지 않는다. 타임아웃 자체가 네이티브 작업 취소를 뜻하지는 않는다.
- 추가 lossless 인코딩의 CPU 비용은 존재한다. 운영 Render 인스턴스의 지연·메모리·BUSY/timeout
  비율은 배포 후 측정한다.
- 기존 로컬 OCR·QR·검수 경로와 승인 전 비공개 원칙을 유지한다. 축소로 작은 글자가 사라질 수
  있으므로 실제 사용자 이미지의 OCR·QR 탐지 품질 검증은 별도로 필요하다.
- AI 모델, 호출 설정, 자동 승인/공개 게이트는 변경하지 않는다. 기기별 검사 호출을 추가하지 않는다.
  파일 바이트 감소가 AI 이미지 토큰 비용의 동일한 감소를 뜻하지 않으며, 기존 모델용 전처리도 유지한다.

## 검증과 적용

- 자동 테스트: 세로·가로·정사각형 최대 해상도, 작은 파일 확대 방지, 양쪽 내용 보존, 방향·알파·메타데이터,
  MIME·용량 제한, 타임아웃 이후 동시 처리 제한, Staging 검수 근거 저장
- 합성 사진 테스트: 기존 1600px/품질84 대비 파일 크기 15% 이상 감소 및 동일한 1280px 기준 픽셀과
  PSNR 32dB 초과 확인. 단일 합성 샘플 결과이며 실제 사진 전체에 대한 절감률이나 품질 보장은 아니다.
- 단색·글자 PNG 테스트: lossless 선택 시 디코딩 픽셀 일치와 기존 WebP보다 작은 용량 확인
- UI 테스트: 이미지 확대와 투표 분리, 로딩 실패, 닫기·ESC·배경 닫기, 포커스·스크롤 복귀, 결과 이미지 쌍
- 브라우저 확인은 실제 공용 컴포넌트와 전역 스타일을 불러온 로컬 fixture에서 수행한다.
  운영 로그인/R2를 사용하는 E2E 검증과 구분한다.

### 로컬 검증 결과

- API: 64개 파일, 446개 테스트 통과 (테스트 전용 로컬 PostgreSQL)
- Web: 50개 파일, 262개 테스트 통과 (`vitest run --maxWorkers=2`)
- lint·typecheck·build: 세 패키지의 9개 작업 통과. 기존 Web 이미지 lint 경고 8개는 유지된다.
- 320·390·767px에서 4:5, 768·1280·1440px에서 16:9와 가로 넘침 없음 확인
- 기본 병렬 `pnpm check`는 기존 피드 자동 로딩 테스트가 간헐적으로 실패한다.
  해당 14개 테스트의 단독 실행과 Web 전체의 worker 2개 실행은 통과했다. 피드 코드는 수정하지 않았다.

위 수치는 최초 로컬 검증 시점의 결과다. 2026-08-30에 운영 배포를 완료했으며 최신 CI와
공개 경로 검증 결과는 [배포 기록](./luna-off-release-2026-08-30.md)에 남겼다.
실제 사용자 이미지 업로드/R2 저장 E2E와 실사용 사진 화질 평가는 별도로 확인한다.

환경변수·DB 마이그레이션·새 의존성은 필요 없다. 서버 배포 후 **새로 처리하는 이미지부터** 저장 정책이
적용된다. 기존 R2 파일은 재압축·교체하지 않는다. 웹 배포 후 표시 비율은 기존 공개 이미지에도 적용된다.

롤백은 이전 API/Web 버전 재배포로 가능하다. 이미 생성된 1280px 파일을 이전 버전으로 배포한다고
1600px로 복구할 수는 없다. 기존 검수·권리·공개 이력은 변경하거나 삭제하지 않는다.
