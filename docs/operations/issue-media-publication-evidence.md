# WHICH-105 — 제출 검사 근거 해석과 결정 엔진 연결

작성일: 2026-08-30. 상태: 내부 근거 해석·결정 평가 연결 구현. 자동 공개 실행과 운영 활성화는 미완료.

## 구현한 연결

`현재 제출/이미지/규칙 근거 + 현재 계정/권한/동의 → 근거 9종 → WHICH-103 결정 엔진`

기존 공개 준비 진단은 보류 코드를 나열했다. 이번 연결은 그 원자료를 내부에서 다시 읽고
`publicationReadiness.decisionAssessment`에 검사별 상태와 결정 엔진의 반환을 기록한다.
클라이언트의 PASS, Provider 응답의 clearScore/provisionalEvidence, 저장된 준비 진단은 입력으로 신뢰하지 않는다.

| 근거           | 실제 확인 내용                                                                        | 현 상태                                    |
| -------------- | ------------------------------------------------------------------------------------- | ------------------------------------------ |
| TECHNICAL      | A/B 소유권·비공개 상태·원본/정규화 hash, 정확한 단계의 정규화 근거 ID·버전·시각·중복  | 일치하면 PASS                              |
| KNOWN_BLOCK    | 현재 활성 exact hash 차단 목록                                                        | 일치하면 FAIL                              |
| LOCAL_PII      | 등록된 로컬 검사기·ENFORCE·OCR/QR/바코드 완료, 원문 대신 개인정보 후보/코드 발견 근거 | 불완전·위험 근거는 REVIEW                  |
| LOCAL_VISUAL   | 실제 시각 검사 구현 여부                                                              | UNAVAILABLE 유지                           |
| IMAGE_SAFETY   | A/B와 문맥에 결합된 Provider 범위·결과·OCR 근거                                       | 검증된 저위험 판정 근거가 없어 PASS 미발급 |
| CONTEXT_SAFETY | 같은 제출 수정본의 텍스트·이미지 검사 결과                                            | 검증된 저위험 판정 근거가 없어 PASS 미발급 |
| RIGHTS         | 현재 자산의 ASSERTED/CLEARED 선언 상태                                                | 소유권/저작권의 법적 판정이 아님           |
| CAPABILITY     | 같은 ACTIVE 회원, 현재 정책의 ACTIVE grant와 발급·만료 시각                           | 철회·정지·만료·다른 회원은 REVIEW          |
| CONSENT        | 같은 회원의 현재 요구 버전, 수락 시각, 미철회                                         | 누락·구버전·철회는 REVIEW                  |

수정본/hash 불일치, 취소/게시 완료, 비공개 상태 상실, 잘못된 소유권,
비활성 회원 또는 미등록 Run 정책이면 모든 체크의 PASS 발급을 보류한다.
Shadow 정책 `moderation-shadow-v1`과 결정 정책 `1.0.0`은 다른 버전 축으로 검사한다.

## 실행 권한과의 구분

- 현재 Provider는 검증된 `NO_POLICY_VIOLATION` 신호를 발급하지 않는다. 낮은 위험 점수나 LOW band를
  안전 확률로 뒤집거나 A/B 합산 응답을 독립적인 두 증거로 세지 않는다.
- 따라서 결정 엔진에 신호를 임의로 만들어 넣지 않는다. 모든 자동화 환경변수를 켜더라도
  미지원 시각 검사·누락된 저위험 근거 때문에 이 경로는 REVIEW다.
- `executionAuthorized`는 항상 false다. 이것은 실행 토큰, 공개 작업 예약, 승인 또는 제재가 아니다.
- 필수 관찰 근거는 입력 hash·정책·출처 ID·관찰 시각에 결합된다. 관찰 유효 시간은 최대 5분이며,
  CAPABILITY는 grant 만료보다 길지 않다. 이 유효 시간은 스냅샷 재사용이나 공개를 허가하지 않는다.
- 개인정보는 일부 휴리스틱으로만 검사한다. LOCAL_PII PASS가 모든 개인정보 제거를 보증하지 않는다.
- 미지원 시각 검사, 대표 표본 기반 저위험 판정, 현재 권리 사건·제재·privacy·예산·출시 승인 등 최종 검증,
  실제 공개/회수 실행은 여전히 후속이다. 완료 전 자동화 플래그를 바꾸지 않는다.

## 저장·조회

worker가 현재 수정본과 자산을 잠근 기존 완료 트랜잭션에서 근거를 읽고 Run 관찰 결과에 저장한다.
검사 중 수정/취소/격리 또는 lease 상실 시 기존 stale 처리 경계를 유지한다.
회원/권한/동의의 조회는 실행용 원자적 잠금이 아니다. 미래 실행부는 실행 직전에 전부 다시 검증해야 한다.

```bash
node apps/api/dist/moderation-worker.js diagnose-publication <submission-id>
```

이 명령은 과거 관찰 결과를 승인으로 재사용하지 않고 현재 DB를 다시 읽는다.
권한을 EXPIRED로 갱신하거나 과거 Run을 덮어쓰지 않으며 OpenAI/R2 호출도 하지 않는다.
Provider 캐시에는 제출별 결정/접근 근거를 넣지 않는다.
기록은 상태·사유 코드·불투명 근거 ID·버전·시각이며 질문 본문, OCR 원문, 연락처, 키를 복사하지 않는다.

기존 `ISSUE_MEDIA_CONSENT_VERSION`과 결정 엔진 환경변수를 worker에도 명시적으로 연결했다.
새 환경변수·키·모델·DB migration은 없다. 실제 Render 설정을 변경하지 않았다.
운영 진단이 실제 최신 동의 버전을 사용하도록 API와 worker는 동일한 동의 버전 설정을 사용해야 한다.

## 검증과 다음 단계

- 순수 해석기: 근거 9종, 만료·철회·다른 회원·구정책·미래 시각·중복·잘못된 단계·hash·개인정보·위조 결과.
- 로컬 DB와 mock Provider: 저장 시점 및 재조회 시점의 동의/권한 재검증, 조회 무변경,
  Provider 캐시 미포함, 원문 미기록, 공개 호출 없음.
- 코드 테스트는 실제 안전 분류 정확도, Render 자원 적합성 또는 운영 이미지 E2E 증빙이 아니다.

다음 연결은 실제 시각 검사와 검증된 저위험 신호 공급, 공개/회수 실행부 및 WHICH-111 운영 검증이다.
정상 저위험 이미지는 관리자 매번 승인 없이 게시하고 예외만 검토한다는 최종 방향은 유지한다.
