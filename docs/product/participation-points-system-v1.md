# WHICH Participation Points System v1

Status: Product proposal  
Working name: `W Point`  
Scope: Member participation reward, non-cash community economy

## 1. 목적

WHICH의 포인트는 사용자가 퀘스트 목록을 의식적으로 수행하게 만드는 장치가 아니라, 평소의 정상적인
서비스 참여에 자연스럽게 따라오는 보상이어야 한다.

핵심 목표는 다음과 같다.

- 로그인한 Member의 재방문과 정상 투표를 늘린다.
- 결과 공유와 다른 의견 탐색을 가볍게 장려한다.
- 포인트를 프로필·공유 카드·수집 요소에 사용하게 해 장기적인 참여 동기를 만든다.
- 투표 결과, Feed 순위, Moderation 판단에는 포인트가 영향을 주지 않게 한다.
- 댓글·질문을 포인트 획득 수단으로 만들지 않아 저품질 콘텐츠 생산 동기를 줄인다.

## 2. 제품 원칙

### 2.1 퀘스트를 만들지 않는다

- 일일·주간 퀘스트 목록과 완료 강제 UX를 제공하지 않는다.
- 사용자는 평소처럼 로그인하고 투표하고 공유하면 포인트를 받는다.
- `/me`에서는 오늘 할 일 대신 현재 포인트, 최근 적립 내역, 사용 가능한 보상을 보여준다.
- 일일 상한은 어뷰징 방지 규칙이지 사용자에게 달성을 요구하는 목표가 아니다.

### 2.2 모든 금액은 10 단위를 사용한다

- 최소 지급 단위는 `10P`로 한다.
- 화면에서 체감되는 보상 크기를 확보하고 향후 상품 가격을 조정하기 쉽게 한다.
- 데이터베이스에는 정수로 저장하며 소수점 포인트를 사용하지 않는다.

### 2.3 현금과 분리한다

- W Point는 충전, 현금 환급, 사용자 간 송금, 판매를 지원하지 않는다.
- 투표 가중치, 콘텐츠 노출 순위, 신고 영향력, 운영자 승인에 사용할 수 없다.
- 초기 사용처는 디지털 꾸미기, 수집, 기간 한정 이벤트로 제한한다.
- 실물·현금성 경품 또는 확률형 응모를 도입할 경우 별도의 법률·약관·연령·세무 검토를 선행한다.

### 2.4 포인트는 Member에게만 귀속한다

- Guest는 포인트 계정을 가지지 않는다.
- Guest 상태의 과거 활동에는 초기 버전에서 포인트를 소급 지급하지 않는다.
- Guest Vote가 Member 계정에 연결되더라도 투표 기록만 연결하고 포인트는 로그인 이후 활동부터 적립한다.
- 계정 탈퇴 시 남은 포인트와 구매한 비양도성 디지털 권리는 계정 정책에 따라 함께 소멸한다.

## 3. 포인트 획득 정책

### 3.1 초기 지급표

| 활동                  |    지급량 | 지급 조건                                                         |            상한 |
| --------------------- | --------: | ----------------------------------------------------------------- | --------------: |
| 일일 로그인           |       10P | 활성 Member가 해당 운영일에 처음으로 인증된 사용자 화면을 연 경우 |        하루 1회 |
| 정상 투표             |       10P | Vote가 현재 `ACCEPTED` 상태가 된 경우                             | 하루 10회, 100P |
| 결과 공유             |       10P | 서로 다른 Issue에서 공유 완료 신호가 서버 검증을 통과한 경우      |   하루 2회, 20P |
| 의견 공감             |       10P | 서로 다른 타인의 공개 의견에 공감을 확정한 경우                   |   하루 3회, 30P |
| 관심사 최초 설정      |       50P | 유효 관심사 설정을 최초 저장한 경우                               |      계정당 1회 |
| 공개 프로필 최초 완성 |       50P | 유효 Handle과 소개를 최초 저장한 경우                             |      계정당 1회 |
| 운영 이벤트           | 별도 지정 | 이벤트별 명시된 서버 검증 조건을 충족한 경우                      |   이벤트별 지정 |

일일 반복 활동으로 받을 수 있는 기본 최대치는 `160P`다.

```text
로그인 10P
+ 정상 투표 최대 100P
+ 결과 공유 최대 20P
+ 의견 공감 최대 30P
= 하루 최대 160P
```

### 3.2 사용자 유형별 예상 적립량

| 유형          | 하루 행동 예시                           | 하루 예상 | 30일 예상 |
| ------------- | ---------------------------------------- | --------: | --------: |
| 가벼운 사용자 | 로그인 + 투표 3개                        |       40P |    1,200P |
| 일반 사용자   | 로그인 + 투표 5개 + 공유 1개             |       70P |    2,100P |
| 적극 사용자   | 로그인 + 투표 10개 + 공유 2개 + 공감 3개 |      160P |    4,800P |

실제 가격은 출시 후 적립 분포의 중앙값과 상위 10%를 확인하여 조정한다.

### 3.3 일일 로그인 정의

`일일 로그인`은 OAuth 또는 이메일 인증 절차를 매일 다시 수행한다는 의미가 아니다. 유효한 Member
세션으로 해당 운영일에 처음 WHICH 사용자 화면을 연 것을 의미한다.

- 운영일 기준 시간대는 초기에는 `Asia/Seoul`로 고정한다.
- 동일 Member는 기기·브라우저 수와 관계없이 하루 한 번만 받는다.
- 백그라운드 API 호출, Prefetch, Health Check, Bot 요청은 출석으로 인정하지 않는다.
- 실제 사용자 화면의 인증된 서버 요청에서 출석을 확정한다.
- 자정 전후 반복 요청에도 unique 제약으로 운영일당 한 번만 지급한다.

### 3.4 결과 공유 정의

브라우저와 운영체제는 메시지가 실제 상대에게 전달됐는지 보장할 수 없다. 따라서 WHICH에서 말하는
`공유 완료`는 다음 중 하나가 성공한 상태다.

- `navigator.share()`가 성공으로 종료됨
- 공유 링크가 클립보드에 정상 복사됨
- WHICH가 직접 제공하는 지원 대상 공유 Adapter가 성공 응답을 반환함

공유 버튼을 단순히 누른 시점에는 지급하지 않는다. 단, 클라이언트 성공 신호는 위조할 수 있으므로
서버가 다음 조건을 다시 확인해야 한다.

- 로그인한 활성 Member인가
- 공개·공유 가능한 Issue인가
- 같은 Member와 Issue 조합으로 이미 공유 보상을 받았는가
- 해당 운영일의 공유 적립 상한을 넘지 않았는가
- 요청의 Idempotency Key와 Share Intent가 유효한가

실제 외부 전송 여부를 알 수 없다는 한계 때문에 공유 보상은 하루 `20P`로 낮게 제한한다.

### 3.5 정상 투표 정의

- 포인트는 Vote Request가 아니라 현재 `ACCEPTED`인 Vote Fact를 기준으로 지급한다.
- 같은 Issue에 대한 재시도, 중복 요청, 선택 변경 시도에는 추가 지급하지 않는다.
- 투표가 나중에 `INVALIDATED` 또는 부정행위로 확정되면 대응하는 포인트를 회수한다.
- 투표 복구 시 기존 지급 원장을 복구하거나 새 보정 원장을 만들되 총 지급량은 한 번분만 유지한다.

### 3.6 포인트를 지급하지 않는 행동

- 댓글 작성과 답글 작성
- 질문 초안 작성, 질문 제출, 운영자 승인
- 공유 창을 열었다가 취소한 경우
- 본인의 의견에 공감한 경우
- 공감을 눌렀다가 짧은 유예 시간 안에 취소한 경우
- 같은 Issue 또는 같은 의견을 반복 조작한 경우
- 테스트·운영자·자동화 계정의 제외 대상 활동

## 4. 포인트 사용처

포인트 사용처는 사용자의 표현 범위를 넓히되 의견의 영향력은 구매할 수 없게 설계한다.

### 4.1 프로필 꾸미기

| 상품군             | 예시                       |    권장 가격 |
| ------------------ | -------------------------- | -----------: |
| 프로필 포인트 컬러 | Cyan·Orange 외 시즌 색상   |     500~800P |
| 아바타 프레임      | 기본형·계절형·이벤트형     | 1,000~2,500P |
| 프로필 배경 패턴   | Grid·Wave·Minimal 패턴     | 1,000~2,000P |
| Handle 장식        | 작은 심볼 또는 밑줄 스타일 | 1,500~2,500P |
| 프로필 카드 테마   | 프로필 전체 색상 조합      | 2,000~4,000P |

프로필 꾸미기는 공개 프로필을 켠 Member에게만 외부 노출한다. 비공개 프로필에서도 본인은 구매하고
미리 볼 수 있다.

### 4.2 칭호와 배지

| 상품군           | 예시                           |            권장 가격 |
| ---------------- | ------------------------------ | -------------------: |
| 일반 칭호        | `오늘도 선택함`, `균형 탐색가` |           800~1,500P |
| 시즌 칭호        | 여름·연말·서비스 기념 칭호     |         1,500~3,000P |
| 수집 배지        | 특정 시즌 참여 기념            |         2,000~4,000P |
| 포인트 달성 배지 | 누적 적립 Milestone            | 구매 불가, 자동 지급 |

- Moderation 권한이나 신뢰도를 암시하는 칭호는 판매하지 않는다.
- `전문가`, `공식`, `운영자`, `검증됨`과 혼동될 수 있는 표현은 금지한다.
- 활동 성취 배지와 포인트 구매 상품은 UI에서 명확하게 구분한다.

### 4.3 결과 공유 카드 꾸미기

| 상품군             | 예시                   |    권장 가격 |
| ------------------ | ---------------------- | -----------: |
| 공유 카드 배경     | Solid·Gradient·Pattern |   500~1,200P |
| 결과 막대 스타일   | Minimal·Neon·Paper     |   800~1,500P |
| 카드 스티커 팩     | 계절·감정·기념일       |   500~1,000P |
| 프리미엄 카드 테마 | 배경·막대·타이포 세트  | 1,500~3,000P |

- 꾸미기는 결과 수치나 질문 문구를 가리지 않아야 한다.
- A는 Cyan, B는 Orange라는 기본 의미 체계는 테마에서도 유지한다.
- 개인이 고른 선택은 현재 공유 프라이버시 정책에 따라 기본 비공개로 유지한다.
- 구매한 테마는 Web과 Mobile에서 공통으로 사용할 수 있게 한다.

### 4.4 앱·Feed 외형 꾸미기

| 상품군                  | 예시                        |    권장 가격 |
| ----------------------- | --------------------------- | -----------: |
| 개인용 Feed Accent      | 본인 화면의 강조색 변형     | 1,000~2,000P |
| 카드 모서리·밀도 프리셋 | Compact·Soft·Square         | 1,000~2,000P |
| 모바일 앱 아이콘        | 시즌별 앱 아이콘            | 2,000~4,000P |
| 완료 모션               | 투표 완료 시 짧은 모션 세트 | 1,500~3,000P |

외형 설정은 해당 사용자 화면에만 적용하고 다른 사용자의 접근성이나 결과 해석에 영향을 주지 않는다.
모션 상품은 `prefers-reduced-motion`과 기기 모션 감소 설정을 항상 우선한다.

### 4.5 컬렉션

상점에서 구매한 항목은 `내 컬렉션`에 영구 보관한다.

- 프로필 프레임
- 배지와 칭호
- 공유 카드 테마
- 스티커 팩
- 앱 아이콘
- 시즌 기념품

컬렉션 항목에는 `OWNED`, `EQUIPPED`, `EXPIRED`, `REVOKED` 상태를 둔다. 영구 상품은 만료되지
않으며, 기간제 상품은 구매 전에 종료일을 명확히 표시한다.

### 4.6 시즌 상점

상시 상품만으로 포인트가 계속 쌓이는 문제를 줄이기 위해 분기 또는 시즌 단위의 한정 상점을 운영할
수 있다.

- 판매 기간과 사용 가능 기간을 구분한다.
- 재판매 가능성을 사전에 표시한다.
- 구매를 놓치면 핵심 기능이 제한되는 상품은 만들지 않는다.
- 지나친 희소성·카운트다운으로 결제를 압박하지 않는다.
- 시즌 종료 후에도 구매 내역과 소유권을 확인할 수 있게 한다.

### 4.7 커뮤니티 공동 목표

개인 간 포인트 송금 대신 포인트를 소모하는 공동 목표를 운영할 수 있다.

예시:

- 전체 사용자가 일정 포인트를 모으면 기념 공유 카드 테마 공개
- 특정 캠페인 기간에 공동 목표를 달성하면 모든 참여자에게 배지 지급
- 포인트 기여량은 공개 순위가 아니라 구간 또는 참여 여부만 표시

공동 목표에 사용한 포인트는 특정 사용자나 Creator에게 이전되지 않고 시스템에서 소각한다.

### 4.8 이벤트 응모

초기에는 디지털 상품을 확정 교환하는 방식이 우선이다. 추첨형 응모를 나중에 도입할 경우 다음을
준수한다.

- 응모권 1장 가격 예시: `100P`
- 이벤트당 Member별 최대 5장
- 당첨 확률 또는 선정 방식, 기간, 대상 지역, 지급 조건 공개
- 운영자·테스트 계정 참여 금지
- 응모 완료 후 임의 취소 불가 여부 명시
- 실물·경제적 가치가 있는 경품은 법률·약관 검토 완료 후에만 진행

## 5. 권장 초기 상품 가격과 경제 밸런스

가벼운 사용자가 약 2~5주 참여하면 원하는 상품 하나를 얻는 정도를 목표로 한다.

| 상품               | 초기 가격 | 가벼운 사용자 예상 소요 |
| ------------------ | --------: | ----------------------: |
| 기본 포인트 컬러   |      500P |                 약 13일 |
| 공유 카드 배경     |      800P |                 약 20일 |
| 일반 칭호          |    1,200P |                 약 30일 |
| 아바타 프레임      |    2,000P |                 약 50일 |
| 프리미엄 카드 테마 |    3,000P |                 약 75일 |

출시 후에는 다음 지표로 가격을 조정한다.

- 일간·월간 Member별 적립량 중앙값
- 상위 10% 적립량
- 포인트 적립 대비 사용 비율
- 첫 상품 구매까지 걸린 일수
- 미사용 잔액 분포
- 상품별 장착률과 재사용률

가격을 바꿔도 이미 구매한 상품을 회수하거나 추가 금액을 요구하지 않는다.

## 6. 사용자 경험

### 6.1 포인트 적립 알림

행동 성공 후 화면 흐름을 막지 않는 작은 알림을 사용한다.

```text
투표 완료 · +10P
```

- 결과 확인과 다음 질문 CTA를 가리지 않는다.
- 같은 화면에서 여러 적립이 발생하면 합쳐서 표시할 수 있다.
- 포인트 API 장애가 투표·공유·공감 본 기능을 실패시키면 안 된다.

### 6.2 `/me` 요약 카드

기존 오른쪽 안내 카드 위치에는 다음 정보를 제공한다.

```text
W POINT

2,480P
이번 달 +620P

포인트 내역 · 상점 →
```

퀘스트 진행률이나 `오늘 남은 획득량`을 기본 강조하지 않는다. 사용자가 자세히 보기를 열었을 때만
활동별 일일 상한과 오늘 받은 내역을 확인할 수 있게 한다.

### 6.3 포인트 내역

각 항목에는 다음을 표시한다.

- 적립·사용·회수된 포인트
- 사용자에게 이해 가능한 사유
- 발생 일시
- 관련 Issue 또는 구매 상품 링크
- 취소·회수 상태

내부 Event ID, Integrity 판정 근거, 보안 정보는 사용자 화면에 노출하지 않는다.

### 6.4 포인트 상점

상점의 기본 탭은 다음과 같다.

1. 추천
2. 프로필
3. 공유 카드
4. 테마
5. 시즌
6. 내 컬렉션

구매 확인 화면에는 보유 포인트, 차감 포인트, 구매 후 잔액, 상품의 영구·기간제 여부를 표시한다.

## 7. 데이터 모델

### 7.1 `point_accounts`

| 필드                       | 의미                       |
| -------------------------- | -------------------------- |
| `member_id`                | 포인트 소유 Member, unique |
| `cached_balance`           | 빠른 조회용 현재 잔액      |
| `lifetime_earned`          | 누적 적립량                |
| `lifetime_spent`           | 누적 사용량                |
| `version`                  | 동시성 제어 버전           |
| `created_at`, `updated_at` | 감사 시각                  |

`cached_balance`는 원장이 아니라 파생값이다.

### 7.2 `point_ledger_entries`

| 필드                       | 의미                                                |
| -------------------------- | --------------------------------------------------- |
| `id`                       | 원장 ID                                             |
| `member_id`                | 대상 Member                                         |
| `entry_type`               | `EARN`, `SPEND`, `REFUND`, `REVERSAL`, `ADJUSTMENT` |
| `amount`                   | 양수 또는 음수 정수                                 |
| `reason_code`              | 지급·사용 사유 코드                                 |
| `source_type`, `source_id` | Vote, Share, Reaction, Purchase 등 원본             |
| `operation_day`            | 일일 상한 계산용 운영일                             |
| `reverses_entry_id`        | 취소하는 기존 원장 ID                               |
| `idempotency_key`          | 중복 처리 방지 키                                   |
| `metadata`                 | 공개되지 않는 최소한의 버전 정보                    |
| `created_at`               | 원장 생성 시각                                      |

원장 행은 수정·삭제하지 않는다. 정정은 반대 방향의 새 원장 행으로 기록한다.

### 7.3 상점과 보유 상품

- `point_catalog_items`: 상품 정의, 가격, 판매 기간, 상품 유형
- `point_purchases`: 구매 Fact, 결제 원장 ID, 구매 당시 가격
- `member_inventory`: Member가 보유한 상품과 장착 상태
- `point_daily_counters`: 활동별 운영일 지급 횟수와 합계의 빠른 제한 확인

구매와 포인트 차감, Inventory 지급은 하나의 데이터베이스 트랜잭션으로 처리한다.

## 8. 이벤트와 Source of Truth

포인트 적립의 근거는 분석 이벤트가 아니라 서버 Domain Fact다.

| 활동        | Source of Truth                         |
| ----------- | --------------------------------------- |
| 일일 로그인 | 서버가 확정한 Member Attendance Fact    |
| 투표        | 현재 `ACCEPTED`인 Vote Fact             |
| 공유        | 서버가 검증한 Share Reward Claim        |
| 공감        | 현재 유효한 Reaction Fact               |
| 구매        | Point Purchase Fact와 차감 Ledger Entry |

예시 흐름:

```text
VOTE_ACCEPTED Outbox Event
→ Point Policy가 지급 가능 여부 확인
→ Point Ledger +10P 기록
→ Account cached balance 갱신
→ POINT_EARNED Event 기록
```

- Outbox는 at-least-once이므로 소비자는 원본 Event ID를 Idempotency Key로 사용한다.
- 포인트 적립 실패가 원본 투표 트랜잭션을 되돌리지 않게 비동기 처리할 수 있다.
- 지연된 이벤트도 발생 당시 `operation_day`와 정책 버전을 기준으로 계산한다.
- 정책 변경 후 과거 이벤트를 현재 금액으로 다시 적립하지 않는다.

## 9. 어뷰징과 운영 정책

### 9.1 기본 방어

- 활동별 일일 횟수·포인트 상한
- 원본 Event ID와 지급 사유에 대한 unique 제약
- Member 상태와 테스트·운영 계정 제외 여부 확인
- Vote Integrity와 Reaction Moderation 결과 반영
- 비정상 Velocity와 반복 패턴 탐지
- 동일 기기·네트워크 정보는 포인트 소유권의 직접 키로 사용하지 않고 위험 신호로만 사용

### 9.2 회수

- 부정 투표나 조작 활동이 확정되면 기존 적립분만큼 `REVERSAL`을 기록한다.
- 이미 사용해 잔액이 부족하면 음수 잔액을 허용하지 않고 `restricted_debt`를 별도로 기록하거나 향후
  적립분에서 먼저 상계한다.
- 운영자는 잔액 컬럼을 직접 수정하지 않고 사유가 있는 `ADJUSTMENT` 원장을 생성한다.
- 모든 운영자 조정에는 담당자, 사유, 관련 Incident ID를 남긴다.

### 9.3 금지되는 사용처

- 투표 가중치 구매
- Feed·Trending 순위 구매
- 댓글 상단 고정 또는 Moderation 면제 구매
- 신고 영향력 구매
- 계정 제재 해제 구매
- 다른 Member에게 포인트 송금
- Creator에게 환전 가능한 후원

## 10. 포인트 수명과 환불

초기 W Point는 별도 유효기간 없이 유지하는 것을 기본안으로 한다. 소멸 정책을 도입하면 고지·문의·복구
부담이 커지기 때문이다.

- 운영 이벤트로 지급하는 별도 Promotional Point를 만들 경우에만 명확한 만료일을 둘 수 있다.
- 중복 구매나 서버 실패는 자동 환불 Ledger를 생성한다.
- 단순 변심 환불은 디지털 상품의 장착·사용 여부와 약관 검토 후 별도 정책으로 정한다.
- 서비스가 상품을 제거하면 구매 포인트 전액 환불 또는 동등 상품 교환을 제공한다.

## 11. 운영자 기능

운영 대시보드에는 다음 기능이 필요하다.

- Member별 잔액과 원장 조회
- Source Event ID로 지급 내역 검색
- 일간 총 발행·사용·회수 포인트 확인
- 활동별 지급 분포와 상한 도달 비율
- 비정상 적립 계정 탐지
- 사유와 Incident를 요구하는 수동 조정
- 상점 상품 생성·판매 중지·가격 변경
- Ledger와 cached balance Reconciliation Dry Run·Repair

수동 조정과 상품 변경은 Cloudflare Access로 보호된 운영자 Surface에서만 수행한다.

## 12. 분석과 성공 기준

포인트 도입 전후로 다음을 비교한다.

- 로그인 Member의 D1·D7·D30 재방문율
- Member당 Qualified Votes
- 결과 확인 후 다음 질문 이동률
- 공유 성공률과 공유 링크 유입률
- 공감 참여율
- 포인트 적립 Member 중 사용 경험률
- 첫 상품 구매까지 걸린 기간
- 부정 적립 탐지율과 회수율
- 댓글·질문 품질 지표의 간접 악화 여부

포인트 때문에 빈번한 무의미 투표가 늘지 확인하기 위해 투표 속도, 같은 선택 반복 비율, Result 체류 시간도
함께 관찰한다.
